# IV-2-2 Self-review (БД2, 11 дэх долоо хоног)

Хуваарилалтаар манай ажлыг IV-2-5 баг шүүмжлэх ёстой байсан ч БД1-ийн хугацаанд Review PDF ирүүлээгүй. Teams-ийн БД1 пост дээр бусад оюутан техникийн comment бичээгүй. Тиймээс БД2-ын зааврын 3-р хэсгийн алхмыг (ангилах, шийдвэрлэх, засах, дахин турших) өөрсдийн шүүмж дээр хийв.

Шүүмжийг гурван эх сурвалжаас цуглуулсан:

1. БД1 тайлангийн §9 "Хязгаарлалт" болон `src/kmod/REPORT_KMOD.md` §9-д бид өөрсдөө бичсэн, шийдээгүй үлдсэн асуудлууд.
2. `v1.0.1` tag дээрх кодыг (`src/kmod/pid.c`, `src/ui/server.py`) дахин уншиж, kernel-ийн баримт бичигтэй (`include/linux/sched/task.h`, `kernel/fork.c`, `kernel/exit.c`) тулгаж шалгасан.
3. Бусад хоёр багийн (V-1-13, IV-2-5) ажлыг шүүмжлэх үед ашигласан шалгуурыг (README, Release, Manual-ийн нийцэл) өөрсдийн repo-д хэрэглэсэн.

Түвшинг БД2 зааврын дагуу Critical, Major, Minor, Suggestion гэж ангилсан. Critical түвшний асуудал (module ачаалагдахгүй, kernel oops, номын үндсэн шаардлага хангахгүй) олдоогүй.

## S1. `children` жагсаалтыг зөвхөн RCU-ийн дор гүйлгэдэг (Major)

`pid_show()` нь `list_for_each_entry_rcu(child, &task->children, sibling)` ашигладаг. Гэтэл `children`/`sibling` жагсаалтыг kernel RCU-ээр биш, `tasklist_lock`-оор хамгаалдаг (`copy_process()` дахь `list_add_tail(&p->sibling, ...)`, `exit_notify()`/`forget_original_parent()` нь `write_lock_irq(&tasklist_lock)` дор өөрчилнө). RCU нь task_struct-ийг шууд чөлөөлөхөөс сэргийлдэг ч жагсаалтаас салгах, reparent хийх үед гүйлт тасрах, нэг хүүхдийг алгасах, өөр эцгийн жагсаалт руу орох боломжтой. БД1 тайланд үүнийг "ховор зөрүү" гэж хязгаарлалтад бичээд орхисон.

## S2. Олон урсгалтай процессын хүүхэд дутуу, ppid нь TID болдог (Major)

`fork()` хийсэн урсгал үндсэн биш бол kernel хүүхдийг тэр урсгалын `children` жагсаалтад бүртгэдэг (`p->real_parent = current`). v1 module зөвхөн бичсэн task-ийн жагсаалтыг гүйдэг тул браузер, IDE гэх мэт олон урсгалтай процессын зарим хүүхэд модонд харагдахгүй. Мөн эцгийг `task_pid_vnr(real_parent)`-ээр хэвлэдэг тул ppid нь урсгалын TID болж, `ps` болон `/proc/<pid>/stat`-ийн PPID (эцгийн TGID)-аас зөрнө. UI-ийн "Module-ийн ppid ≠ /proc" анхааруулга энэ үед гарна.

## S3. Глобал `l_pid`: зэрэг ажиллахад хариу холилдоно (Major)

Сүүлд бичсэн PID нэг глобал хувьсагчид хадгалагдана. Хоёр хэрэглэгч эсвэл хоёр скрипт зэрэг "бичих, унших" хийвэл нэг нь нөгөөгийнхөө PID-ийн мэдээллийг уншина. UI сервер дотооддоо мутексээр хамгаалдаг ч терминал, бусад программыг хамгаалахгүй. Номын интерфейс (`echo PID > /proc/pid`, дараа нь `cat /proc/pid`) нь хоёр тусдаа нээлт тул энэ асуудал интерфейсийн загвараас үүдэлтэй.

## S4. UI PID 0-ийг зөвшөөрдөг, module татгалздаг (Minor)

`server.py`-ийн `parse_pid()` 0..PID_MAX_LIMIT-ийг хүлээн авдаг. Module 0-д `EINVAL` буцаадаг тул хэрэглэгч "Module оролтыг татгалзлаа: Invalid argument" гэсэн ойлгомж муутай алдаа харна. Алдааны мессеж дэх "0..4194304" муж ч буруу.

## S5. `__state` тоог тайлдаггүй (Minor)

Module номын дагуу `__state`-ийг тоогоор (жишээ нь `8193`, `260`) хэвлэдэг. UI үүнийг тайлахгүй, үсгэн төлөвийг `/proc/<pid>/stat`-аас авдаг тул дүрслэл дээрх төлөв module-ийн өгөгдлөөс биш procfs-оос ирж байна. Тайланд битийн утгыг гараар тайлбарласан.

## S6. Өвөг эцгийн гинж procfs-оос ирдэг (Minor)

"book" горимд module эцгийг хэвлэдэг ч UI PID 1 хүртэлх өвөг эцгийн гинжийг `/proc/<pid>/stat`-аас уншдаг. Үндсэн дүрслэлийн нэг хэсэг module-ээс биш.

## S7. Баримт бичиг хуучирсан (Minor)

README "Бие даалт 1", "Шүүмжлэх баг: IV-2-5" гэж бичигдсэн (бид V-1-13-ийг шүүмжилсэн). Quick Start "Ubuntu 22.04" гэдэг ч туршсан нь 24.04, 26.04. README-д screenshot байхгүй. `contract_check.py` болон тайланд ✔/⚠/✖ тэмдэг үлдсэн.
